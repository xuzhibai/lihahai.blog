## 值得一看

### 1. tw93的开源故事：独立开发者的第一步是先解决自己的需求

**原文链接**: [未来硅世界16期：tw93的开源故事和经验](https://x.com/vista8/article/2058213893638689266)

tw93 这个名字，关注开源工具的朋友应该不太陌生。妙言、Pake、Mole、Kaku、Kami、Waza——6款工具都是他的作品，上期周刊也推荐过 Mole 和 Kami。

这篇访谈对我来说最大的启发是他做每个工具的初衷：每一个工具都是为了解决他自己的一个实际需求。

Mole 的前身是一个在他本地跑了一年的 Shell 脚本，专门清理程序员电脑上的垃圾缓存。Pake 是因为他喜欢用微信读书但没有桌面端，就用 UI 框架自己打包了一个，代码就几百行，顺手开源了。Kaku 是他 fork 了一个终端工具，在本地改了半年才发出来。

AI 确实把开发门槛打下来了，如今独立开发者也越来越多，但我见过不少人做独立开发，做着做着就成了一个"纯自嗨"的产品——功能一堆，却没人用。

一个产品能成功，绝不只是开发出来这么简单，更难的是表面上看不见的“软技能”：如何理解用户需求和痛点，如何把一个产品持续的运营好。

AI时代独立开发者的第一步是**先用AI做一个能解决自己痛点的工具。你自己就是第一个用户，你天然知道这个场景下最需要什么。** 然后不断迭代。

### 2. Harness Engineering：为什么裸模型0分，加上"马具"就能做生产级软件？

**原文链接**: [一文看懂 Harness Engineering，帮你的AI提效10倍](https://x.com/FakeMaidenMaker/article/2055146731625447516) | [真实Agent迭代案例，真正理解Harness工程](https://mp.weixin.qq.com/s/weEvAb6HHYEqK5T5Q7sNBQ)

两篇关于 `Harness` 的文章，一篇偏理论框架，一篇偏产品经理视角的实操。

说实话，这两篇文章是第一次让我清晰理解 `Harness` 到底是什么、为什么要这个东西的。印象中应该是 Claude Code 这类 Agent 工具先提出了任务规划、上下文管理、Skills 这些功能，后面才有的 `Harness` 这个概念。之前零零散散看过一些文章，不成体系也看的稀里糊涂。

推荐先看实操这篇，从一个实际的需求开始，从零构建一个写作 Agent ，一步一步解决遇到的每一个问题，最终形成的这一整套能让模型能力变得更强、更稳定的工程基础设施，就是“Harness”。

理论篇则是结合 Claude Code、Codex 这些产品的实践，从上到下将 `Harness` 拆分为了 5 个核心维度：上下文管理、执行能力、任务编排、反馈机制、架构护栏。

看完这两篇应该可以对`Harness Engineering`有个清晰的理解。

### 3. 除了工作和收入，还有什么在支撑你的价值感？

**原文链接**: [E234 当我不再被工作定义！5 个普通人的价值感重建时刻｜小酒馆故事会 🍻](https://youzhiyouxing.cn/materials/2182)

这是知行小酒馆的一期播客，他们向听友征集了一个问题：**除了工作和收入之外，还有什么在支撑你的价值感？** 选了 5 个普通人的故事。我特别喜欢其中两个。

第一个是小杨，一个从河南新乡到北京、上海打拼的编剧。曾经极度投入工作，靠写作改变了自己的生活。转折点发生在产后职业倦怠、母亲重病、女儿出生——三重压力下，她决定带全家回河南老家。

她的价值感从"成为有名有号的大编剧"转向了"认真过好当下"。

她关于生命的两端（新生与临终）的描述很让我触动，比如她女儿第一次学会翻身："每一个人的人生，也曾在最初为了一次翻身而如此努力。"还有在老家晚饭后散步的场景——大家聊家人、聊追星、聊对象、聊动物，**没有人聊工作，也没有人聊AI。** 每个人都好快乐。

有时候想想，城市里的快节奏确实让我们的感受力变低了，对生活的热爱更少了。不愧是编剧，能把生活写得这么细腻。

另一个是自称"互联网大厂女工"的盖饭。求职期间极度焦虑，把所有价值绑在"找到工作"上。转折点是春节回家，和朋友、外婆相处，放松下来后反而顺利拿到 offer。后来外婆突然去世，家人一直瞒着她，直到她临时回家才知道。

再后来因为工作压力，身体出了问题，一个人去做手术。但手术那天，她久违地在工作日看到了西湖的落日——**原来工作日的午后也可以这么美。**

这些事让她意识到一件事：生活不能只有一个支点。工作之外，健康、爱好、朋友、家人同样重要。

这期播客里有一句话我很喜欢："如果当下的生活，是你十年后还想过的生活，那它就有意义。"

跟我们今天聊的 `Harness` 工程和独立开发放在一起看，让我有一种说不上来的感觉。有时候我会问自己——我们花很多精力去"驾驭" AI 、拼命工作、关注那些看起来宏大的叙事以及虚无缥缈的东西，这些真的重要吗？

好像我也很久没有停下来看看落日了。

## 4.AI干活太差，试试让它反问你几个问题

**原文链接**:[会让AI反问你，才是AI视频高手的分水岭](https://waytoagi.feishu.cn/wiki/Lo1bw5ILwiptq6k4amecsXAhnqe)

一篇 AI 使用技巧。核心观点很简单：试着让 AI 反问来澄清需求。

说来惭愧，这也是我最近才学会的。我之前也零零散散学过如何写提示词，但是很多时候AI还是get不到我的点或者需要反复修改。

AI的脑子中有整个互联网上的知识，但是他并不知道你的偏好，或者说你没说清楚的隐含的需求，所以他只能给你一个差不多的答案。

我现在每次跟 AI 描述完自己的想法后，都会加一句"如果有没讲清楚的或者有需要补充的信息，你也可以向我提问"。反复几轮下来效果确实好很多，甚至有时候 AI 还能帮我发现我自己都没想到的点。

## 哆啦百宝箱

### 1. Understand-Anything — 把任意代码库变成交互式知识图谱

**链接**: [GitHub](https://github.com/Lum1104/Understand-Anything)

一个 Claude Code 插件，用 Tree-sitter + LLM 混合方式分析你的项目，生成可视化知识图谱。每个文件、函数、类都是一个节点，可以搜索、点击查看关系、自动生成架构浏览路线。

其实AI 刚火的时候就有工具能给 GitHub 仓库自动生成项目文档（比如 deepwiki，把链接里的域名一换就能跳转到生成的文档）。这个更进一步——能给项目代码生成一个可交互的可视化 wiki。

对于理解那些缺乏文档维护、技术债积累过多的大型项目还挺有帮助的，甚至能直接用来内部分享和评审。唯一的缺点就是，分析大型项目的 token 消耗爆炸，还有大模型在线分析代码隐私方面的考量，当然如果能本地部署大模型这些都不是问题。

我上大学那会很喜欢折腾 Windows 美化，当时用 Rainmeter 在桌面加各种插件和系统监控，也试过把 Windows 美化成 macOS 风格。不过那些软件能自定义的程度其实很低，只是桌面好看了而已，一打开文件管理器就露馅了。
